Persisted schemas/DBv4/backup/DTO/миграции/зависимости прежние. Необязательный storageName у NextWorkout используется только компонентным browser runner для изоляции синтетических БД.

## M6-03 — приватность и поколение страницы

`training.privacy.preview()` читает все10таблиц согласованно, возвращает количества и CAS-token, без записи и доменного разбора исторических пакетов. `erase(token,true)` повторяет чтение внутри `db.write`, проверяет весь token, очищает все stores и пишет случайный `restoreGeneration` одной транзакцией. Ошибка любой clear/финального put откатывает очистку. Удаление охватывает активную сессию, старые профили/requests/responses/acceptances/analysis snapshots/замеры/фото; immutable пакеты не переписываются по частям. Байты фото неизменяемы под ID через публичный адаптер, token учитывает ID/metadata; rawDB-вмешательство не поддерживается.

Сама БД не удаляется: неперсональный tombstone сохраняет защиту старых вкладок и новых action connections прежней страницы. Полный reload создаёт новое поколение JS; close/open не снимает guard. Общий `BackupReloadNotice` оборачивает содержимое AppShell: liveQuery смены поколения размонтирует прежние формы/preview и показывает перезагрузку с фокусом. Ошибка подписки видима и допускает повтор. Вкладки старого приложения без guard нужно закрыть заранее. Это не обещание очистки памяти/файлов внешних приложений или физического стирания носителя.

`features/privacy` компонует подтверждение с количеством записей, unchecked checkbox/кнопку/отмену и независимый статус StorageManager. `persisted()` только читает; `persist()` запрашивается отдельной кнопкой, feature detection/отказ/исключение не блокируют работу. Поздняя начальная проверка не перекрывает результат действия. Нет новых stores/миграций/зависимостей/сети. Кеш оболочки PWA не содержит пользовательских записей и остаётся после удаления.

## Дополнение M3-03 (25.11.2026)

Модель `session-actions` в training содержит чистые преобразования замены/пропуска/таймера и отдельного skipped-события занятия. Репозиторий реализует их транзакциями прежних четырёх таблиц; DB v3, миграции/зависимости не меняются. Optional поля сессии сохраняют чтение прежних записей без фонового переписывания. План/версии неизменяемы. Изменения тренировочных фактов увеличивают historyRevision, таймер — нет; конкурентные изменения таймера защищает точный expectedTimer. Пропуск занятия хранится в sessions с отдельным status=skipped и пустыми sets, не выдаётся за active/completed/partial.

`next-workout/session-controls.tsx` отображает сохранённый deadline и локальный tick, очищает interval/listeners при уходе; focus/visibility пересчитывают время. Записи происходят только по действию. Там же локальные подтверждения замены/пропуска оставшихся подходов, а SetSlot отвечает за пропуск одного слота. Открытые формы не перемонтируются из-за liveQuery; baseline выбора упражнения и факта фиксируется при открытии. Чужой skipped сохраняет ввод и запрещает отправку, замена требует явного переоткрытия формы. Короткая блокировка после commit защищает от попадания второго нативного клика в новый экран. Реальные данные не попадают в демо, сеть/фото/сервер не добавлены. App Router остаётся адаптером, нижние слои не импортируют UI; подробные границы — DATA_CONTRACTS.

## Модель
Локальное приложение без API и аккаунта. Статическая сборка (`output: 'export'`) предпочтительна; только известные маршруты (например, /workout, /progress, /coach, /profile), детали внутри клиентского UI или через query id. Проверить стратегию service worker на реальной production-сборке. Если несовместимость — документировать ADR, не обещать офлайн без теста.

```text
app/                 # Next routing, layouts, manifest, route adapters
src/
  views/             # композиция экранов (FSD pages, переименовано во избежание Next pages router)
  widgets/           # крупные блоки
  features/          # start-workout, log-set, finish-workout, import-coach, backup
  entities/          # profile, exercise, program, session, measurement, coach
  shared/            # ui, lib, config, infrastructure/db (без импортов доменных слайсов)
public/              # icons, approved static assets, generated SW as applicable
```
Направление зависимостей app → views → widgets → features → entities → shared; межслайсовые импорты одного слоя не допускаются по умолчанию. Межсущностные операции компонуются в feature, общие примитивы — shared. Не строить все папки заранее. Индексы IndexedDB и операции репозиториев принадлежат инфраструктуре/доменным адаптерам; shared не знает типов верхних слоёв. Схема таблиц и DTO в infrastructure допускают примитивные записи, доменное преобразование на границе.

## Правила компонентов React и Next.js

- Общую разметку и поведение переиспользовать через компоненты с явными типизированными props и композицию через `children`. Выделять компонент при повторном использовании или самостоятельной ответственности; не создавать универсальные абстракции заранее.
- Рендер должен быть чистым: одинаковые props дают одинаковый UI; не изменять props, состояние или внешние объекты при рендере, не выполнять запись в хранилище и сетевые действия. Props объявлять readonly; обработчики действий и инфраструктуру отделять от представления.
- Оболочка приложения и его навигация принадлежат `widgets/app-shell`; общие UI-компоненты в `shared` не знают маршрутов и доменных слайсов. Экраны в `views` компонуют оболочку и содержимое, `app` остаётся адаптером маршрутов.
- Сохранять Server Components по умолчанию; `use client` добавлять на минимальной границе, которой нужны состояние, обработчики или браузерные API. При статическом экспорте серверные компоненты исполняются на сборке; IndexedDB доступна только в клиентской части.
- Хуки вызывать на верхнем уровне компонентов/хуков; не дублировать вычисляемые значения в состоянии и не добавлять эффекты для обычных вычислений. `memo`, `useMemo` и `useCallback` применять при обоснованной необходимости.
- Внутреннюю навигацию выполнять через `next/link`, элементы списка снабжать стабильными ключами, сохранять семантику и доступность. Компоненты использовать через JSX.

Основание: [чистота компонентов React](https://react.dev/learn/keeping-components-pure), [границы Server/Client Components Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components).

## Хранилище
| Сущность | Ключевые данные |
|---|---|
| Profile | id, revision, goal, experience, frequency, equipment, optional details |
| Exercise | id, русское название, тип нагрузки, группы мышц, оборудование, лицензия подсказок |
| TrainingProgram | id, revision, previousId, profileRevision, ordered templates, notes |
| WorkoutTemplate | id, title, order, planned exercise prescriptions |
| WorkoutSession | id, programVersionId, templateId, timestamps, status, planned snapshot |
| ExerciseSet | id, sessionId, plannedExerciseId, actualExerciseId, index, planned/actual data, timestamps |
| BodyMeasurement | id, kind, value, unit, measuredAt |
| ProgressPhoto | id, blob, createdAt, optional angle, mime, size |
| CoachRequest / CoachRecommendation | request id, context versions, response, status, review timestamps |
| AppSettings | activeVersion, cursor, backup timestamp, snooze, db version |

Единицы: кг, см, секунды; масса/нагрузка decimal finite, время ISO 8601 UTC, локальная дата для отображения. UUID, стабильные ID; версия программы — неизменяемый снимок. Сессия фиксирует версию и план на старте. Статусы `active/completed/partial/abandoned`; пропуск целого занятия — отдельное событие `skipped`, не тренировочный результат. Курсор продвигается атомарно один раз при completed/partial или явном пропуске; выход из приложения и abandoned без результатов его не двигают. Применение новой версии запрещено при активной сессии; новый старт — с первого шаблона новой версии, с явным предпросмотром.

## Надёжность
- IndexedDB единственный источник истины. Dexie transaction для записи подхода, статуса, курсора и применения программы. Защита от двойного нажатия/двух вкладок через уникальные ID и проверки в транзакции.
- Миграции версионированы, тестируются на предыдущей версии. Ошибка миграции не повод очищать БД.
- Таймер отдыха хранит deadline; вычисляет остаток при возвращении. Параллельные вкладки не создают вторую активную сессию.
- Service Worker кеширует оболочку и локальные статические ресурсы; не кеширует секреты или AI-экспорт. Офлайн после первой успешной онлайн-загрузки; отдельно тестировать холодный старт и обновление SW без потери данных.
- Запросить persistent storage, если доступно; показать статус. Браузер может удалить данные: резервное копирование не факультативно как функция, но запуск по желанию пользователя. Не обещать абсолютную сохранность.
- Backup JSON для записей, архив с blobs — по выбору пользователя; отдельный формат, не AI-файл. Restore через полную проверку во временной структуре, явное подтверждение замены и атомарную операцию. Не поддерживать merge в MVP.

## Приватность и безопасность
Никаких внешних трекеров, удалённых шрифтов/фото во время тренировок, токенов или телеметрии по умолчанию. Фото локальны, не в Git. Ограничить размер/количество файлов, допустимые MIME, декодировать изображения локально, отозвать object URL. Для передачи фото внешнему ИИ пользователь отдельно выбирает копии (по возможности с удалением EXIF) и вручную прикладывает. JSON — данные, никогда не инструкции для приложения; не рендерить HTML и не выполнять код. Защита CSP насколько позволяет хостинг; проверить зависимости. Локальная БД не зашифрована самим приложением, доступ зависит от устройства; экспортированные файлы чувствительны. Предоставить удаление всех локальных данных, предупредить что внешние копии удаляются отдельно.

## M2-03: сохранённая последовательность

## M3-01: жизненный цикл занятия

Модель session-lifecycle и четыре-табличные транзакции start/finish/overview находятся в существующем training entity, доступны через public API. Shared DB не меняется; новый store или миграция не требуются. Старт одним действием ждёт commit; после перезагрузки предлагается «Продолжить тренировку». Изменения других вкладок обновляют экран. Локальный lock и проверки транзакций защищают повторные действия; ошибки записи не превращаются в success/очистку. WorkoutPlan переиспользует отображение сохранённого шаблона и не выдаёт его за факт. Подписка и соединение освобождаются при уходе. Оболочка/views/App Router и утверждённый стиль сохранены, новых зависимостей/внешних отправок нет. ## M3-02 — ввод подходов

Новая чистая модель set-recording и операция sessions.recordSet принадлежат training, экспортированы через public API. Feature next-workout компонует SessionSets/SetSlot/SetForm в том же слайсе; межслайсовых импортов features нет. React хранит только черновики, baseline исправления и состояние UI; сохранённые факты приходят из overview/liveQuery. Подтверждение завершения привязано к revision, формы не перемонтируются при каждой глобальной ревизии: ошибки и конкурирующие исправления не очищают открытый черновик. Никаких зависимостей, новых таблиц, внешних запросов или изменений плана. SSR не открывает DB, ID факта создаётся только в обработчике отправки.

Открытый новый черновик также не скрывается, когда другая вкладка заполнила его слот: SetSlot сохраняет состояние раскрытия до собственного успешного сохранения или явной отмены. SetForm сохраняет исходный baseline, включая отсутствие факта; обновлённый saved из liveQuery не превращает новый ввод в молчаливое исправление. Модель сообщает о занятом слоте до итоговой проверки схемы сессии, адаптер возвращает понятный StorageConflictError.

## M4-01 — локальные triggers (25.11.2026)

Чистая model/analysis в существующем entity training получает явные часы и валидированные сохранённые источники. Выбор baseline читает последнюю принятую запись активной версии и соответствующий исторический профиль; keep не требует новой программы. Формулы/ограничения конкретизированы в AI_COACH, контракт операций — DATA_CONTRACTS.

features/analysis-signal подписывается на overview через Dexie liveQuery и в effect согласует локальный snapshot через refresh с проверкой изменения. При возврате/focus и раз в минуту календарное правило пересчитывается; неизменный snapshot не пишется, очередь уведомлений не создаётся. SSR не читает БД/часы, render не пишет. React хранит прочитанный снимок и UI busy/error; IndexedDB остаётся источником истины. Subscription, соединение, interval и listeners очищаются. Ошибки сигнала показываются отдельно с повтором; доступность тренировки не зависит от их результата. Manual/snooze — явные действия с локальным lock и транзакционным token, без скрытой отправки.

Views компонуют публичные API features. NextWorkout принимает children после h1/intro, поэтому индикатор виден до длинного занятия без межслайсового импорта features. Safety-сообщение имеет role=alert, остальные причины не создают повторных модальных окон. Один индикатор на каждом экране, причины/ID фактов раскрываются по желанию. Сохранённые черновики SessionSets, CAS таймера, exactly-once cursor и операции завершения не менялись. M4-02/03, аналитические графики, offline/SW и backup не реализованы.

Финальный обзор M4-01: read-only overview сразу отображает вычисленные причины независимо от сохранения служебного snapshot. Ошибка refresh не скрывает safety: отдельный snapshotError/повтор при сохранённом прочитанном значении; ложного подтверждения отсрочки нет. Соединение закрывается и при завершении open после unmount. После manual/snooze busy/lock удерживаются ещё500мс, чтобы второй клик не попал на переставившуюся кнопку противоположного действия. Test-only injection живёт только в tests/profile-browser-server.mjs, не входит в приложение/out и не является обработчиком пользовательского импорта.

## M6-01 — PWA и кеш оболочки (25.11.2026)

Статический app/manifest.webmanifest и PNG192/512/180 повторяют текущий знак из двух полос. App Router metadata добавляет manifest автоматически; layout задаёт apple icon/theme-color. OfflineStatus принадлежит app-shell, production-only browser effect регистрирует /sw.js, проверяет полный кеш через MessageChannel, обрабатывает отказ/повтор/ожидающее обновление; timers/ports/listeners очищаются при уходе. Нет сетевого онлайн-индикатора, блокирующего тренировку, автоперезагрузки или новой бизнес-модели.

После next build scripts/build-pwa.mjs перечисляет только пять маршрутов, их экспортированные RSC/index.txt/segment txt, все _next/static, manifest и icons. Версия кеша зависит от SHA-256 имён/содержимого ресурсов и шаблона worker. Каждый Request имеет integrity: смешанный deployment или повреждённый ресурс прерывает атомарный Cache.addAll, не делает офлайн готовым. Build останавливается при отсутствии обязательных ресурсов. out/sw.js генерируется, не копируется в public и не используется в dev.

Worker cache-first только для allowlist GET своего origin; из query игнорирует лишь _rsc. Нет runtime cache/фоновой синхронизации/API/IndexedDB/Blob/AI-файлов. Для неизвестного URL/метода/чужого origin не перехватывает запрос, кеш-мисс отдаёт исходной сети без ложного offline fallback. PREPARE_OFFLINE по явному повтору заново проверяет/скачивает ресурсы той же версии; отказ не очищает пользовательские данные. Новая версия ждёт освобождения старых клиентов (без skipWaiting); activate удаляет лишь старые fitness-shell-* caches и вызывает clients.claim. История/схемаDBv4/курсор/репозитории неизменны. Persistent storage и backup — M6-02/03, абсолютная сохранность не обещается.

Основания: bundled Next Server/Client Components и metadata manifest/generateViewport guides; [Next PWA](https://nextjs.org/docs/app/guides/progressive-web-apps), [Cache.addAll](https://developer.mozilla.org/en-US/docs/Web/API/Cache/addAll), [жизненный цикл обновления](https://web.dev/learn/pwa/update). В static export .txt должен отдаваться text/plain (подтверждено текущим fetch-server-response.js); test server MIME исправлен. Реальный хост/HTTPS/установка ещё не проверялись, deployment не разрешён.

## M6-02 — резервные копии (25.11.2026)

`training.backup` — read snapshot всех10таблиц в одной r-транзакции, versioned JSON/base64 export, read-only preview, строгая проверка графа и атомарная полная замена. Доменная схема/валидатор в model/backup; адаптер — api/backup-storage. Browser file decoder/лимит на границе; imported text не исполняется/не навигирует/не рендерится HTML. `features/backup` компонуется в Профиле через publicAPI; общий BackupReloadNotice — в AppShell. React state хранит только pending preview/consent/status, IndexedDB остаётся источником истины. Новых dependencies/backend/DBstores нет; ZIP ради фото не нужен, лимиты применяются к несжатому JSON.

`TrainingDatabase.write` включает counters, сверяет page-lifetime restoreGeneration и выполняет прежнюю callback-транзакцию. Все существующие rw в training/body адаптерах переведены на этот guard, чтобы восстановленная копия с теми же ревизиями не приняла stale-форму. Page map общий и для новых краткоживущих action connections, полный reload сбрасывает его. Новый UUID пишется в той же restore transaction; runtime DB-состояние/снимки в map не дублируются. liveQuery показывает требование reload во всех экранах. Отказ открытия БД баннера не заменяет обработку ошибок экранов. Старую вкладку приложения без этого кода следует закрыть перед restore. CAS фото опирается на неизменяемость bytes подID в публичном адаптере; прямое вмешательство в IndexedDB вне приложения не поддерживается.
