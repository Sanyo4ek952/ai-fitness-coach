# IMP-02 — расширенный обмен программами

Дата: 26.11.2026. Реализация по запросу владельца, продолжение IMP-01.

## Аудит и технический план

Первоначально восемь упражнений ограничивали не только файл, но и prescription, фактический подход, агрегаты истории, повторный AI-запрос, UI и проверку графа backup. Программа не содержала этапов, правил и рекомендаций. `programToDraft` выбирал поля вручную, поэтому простое добавление полей в Zod теряло бы их при diff, повторном экспорте и rollback. Все снимки сессий сравнивались только с базовым шаблоном версии. Сохранённые AI-запросы содержат копию тогдашней JSON Schema, которую также нужно продолжать читать.

Порядок реализации: расширить существующие схемы → определения упражнений внутри неизменяемых версий → фазовый выбор шаблона и атомарный курсор → прежние механизмы import/accept/review/backup → UI → примеры, регрессия и native runner. Отдельного backend, mutable registry, новых stores, библиотек или параллельной схемы типов нет.

## Контракт

Источник истины — Zod в `src/entities/training/model/program.ts`, `exercise.ts`, `program-import.ts`, `coach-request.ts`, `session.ts`. TypeScript-типы выводятся из них. [Полная JSON Schema](../examples/training-program.schema.json) генерируется командой `node scripts/export-program-contract.mjs`; команда также обновляет схему ответа в примере AI-запроса. [Полный пример A/B/C на восемь недель](../examples/training-program.periodized.example.json) демонстрирует все семь категорий, неизвестный вес, гантели, противовес, собственный вес, время, дистанцию, разминочные подходы и пользовательское упражнение. Это синтетический пример контракта, не назначение нагрузки.

Файл остаётся `{"schemaVersion":1,"kind":"training_program","program":{...}}`. Это обратносовместимое расширение optional-полями: прежние файлы и записи не преобразуются и не переписываются. Более старое приложение с прежним строгим валидатором отвергнет новые поля, не потеряет их молча. Обновление приложения необходимо до загрузки расширенного плана. Неизвестные версии/поля по-прежнему отклоняются.

| Поле | Представление и смысл |
|---|---|
| `program.title`, `goalInterpretation` | Прежние строки; порядок `workouts` сохраняется. |
| `workouts[].exercises[]` | Прежние `exerciseId`, `sets`, `target`, `restSec`, optional `rir`, `note`. |
| `definition` у строки | Полное `{id,name,equipment,measurement,load,muscleGroups}` для упражнения вне встроенного каталога. `id` равен `exerciseId`. Для неизвестного ID обязательно в каждой строке и соответствующем override. |
| `target.type=reps` | `min`, `max`, `weightKg:number|null`; фиксированные повторы — `min=max`. Ноль не равен неизвестному весу. |
| `target.type=duration` | `seconds`, optional `maxSeconds`, `intensity`. Фиксированное время — без `maxSeconds` либо с равным максимумом. |
| `target.type=distance` | `meters`, optional `intensity`. |
| `rirMax` | Optional верх RIR, только при числовом `rir`, не ниже минимума. Числовой RIR допустим только для повторов. Для времени/дистанции rir отсутствует либо равен null; явный null сохраняется без подстановки числа. |
| `setPlans` | Optional массив длины `sets`; каждый элемент `{kind: warmup|working,target,restSec,rir?,rirMax?,note?}`. Это полный список, включая разминку; отсутствующий список означает прежние одинаковые рабочие подходы. Единица каждого подхода совпадает с упражнением. |
| `phases` | Optional упорядоченный массив: `id,title,goal,duration,transition,transitionNote?,overrides`. ID уникальны. |
| `duration` | `{unit:"sessions",count}` либо `{unit:"weeks",count,sessionsPerWeek}`. Во втором случае целевой объём равен произведению; календарь и частота профиля не подставляются. |
| `transition` | `after_sessions` проверяет объём выполненных/частичных сессий; `manual` оставляет оценку спортсмену. Оба варианта требуют явного подтверждения. `transitionNote` — текст дополнительного условия, не исполняемый код. |
| `overrides[]` | `{workoutIndex,exerciseIndex,prescription}` с индексами от нуля и полным предписанием строки. Изменяет подходы, цели, вес, RIR, отдых, комментарии, индивидуальные подходы; ID/определение упражнения сохраняются. Дубли позиций и ссылки вне программы отклоняются. |
| `progressionRules[]` | `id,exerciseId?,description,condition,action`; отсутствие exerciseId означает общее правило. |
| `condition` | `type:upper_reps|below_reps|plateau|excessive_load|manual`, `sessions`, optional `minRir,maxRir`. |
| `action` | `{type:"weight",change,unit:"kg"|"percent"}`, `{type:"reps"|"sets",change}` либо `{type:"review",instruction}`. Изменение знаковое, не нулевое; кг помощи не инвертируются автоматически. |
| `recommendations[]` | `{category,text,exerciseId?,phaseId?}`. Категории `technique,warmup,recovery,cardio,nutrition,safety,other`. Ссылки валидируются. |
| `reviewAfterSessions` | 1–10000; анализ больше не ограничен четырнадцатью занятиями для долгосрочного плана. |

Сохраняются технические ограничения 1–14 дней, до 20 упражнений в дне, до 20 подходов в строке, 100 этапов, 200 правил и 200 рекомендаций, до 2 MiB на файл. Ограничения видимы в JSON Schema; неверные значения не обрезаются. Каталог и количество упражнений в долгосрочной истории не имеют прежнего лимита 200. Рекурсивная сложность входного JSON ограничена до Zod: глубина 64, 100000 узлов, запрет опасных ключей. Файлы читаются как строгий UTF-8 JSON; содержимое никогда не исполняется и не открывается как HTML/ссылки.

JSON Schema описывает структуру; связи `min<=max`, совместимость измерений, неизменность определений, уникальность и наличие ссылок дополнительно проверяются runtime-валидатором. Ошибка показывает до пяти проблем с путём поля. Изменения до подтверждения отсутствуют.

## Каталог и подтверждения

Встроенный каталог расширен с 8 до 42 упражнений без изменения прежних ID/метаданных; добавлено оборудование `machine` («Другие силовые тренажёры»). Наличие конкретного оборудования пользователь оценивает сам. Полный доступный каталог при экспорте — встроенные определения плюс определения из всех сохранённых версий. Неизвестное упражнение с неполными метаданными отклоняется; похожая замена не выбирается.

Определения сохраняются в строках версии и снимках/фактах занятия. Это сознательная денормализация неизменяемых метаданных: удаление будущего каталога не меняет историю. Mutable global registry и отдельная таблица не нужны. Один ID нельзя переопределить; одинаковые нормализованные названия под разными ID отклоняются (NFKC, регистр, е/ё, пробелы, пунктуация). Разные названия одного движения автоматически не распознаются как синонимы — решение пользователя, не неявная подмена.

Собственный импорт показывает новые упражнения с русскими метаданными и отдельным unchecked-согласием на добавление. Затем требуется прежнее согласие на весь план. API перепроверяет согласие, оборудование, каталог и CAS в общей write-транзакции; версия и курсор сохраняются атомарно. AI-ответ показывает определения в полном preview; unchecked-согласие на весь пакет явно включает добавление упражнений. `coach.accept(false)` не применяет пакет.

## Этапы, история и прогрессия

Курсор программы optional-полями хранит `phaseIndex` и `phaseSessions`; старые программы остаются с прежним курсором. При старте `selectNextWorkout` выбирает базовую строку либо override текущего этапа. Сессия сохраняет `phaseIndex` и готовый неизменяемый `plannedSnapshot`. Чтение, исправление, аналитика, AI-export и backup сравнивают снимок с соответствующим этапом сохранённой версии. Исторические планы и факты не пересчитываются.

Завершённое/частичное занятие увеличивает счётчик этапа вместе с прежним продвижением дня в одной транзакции. Пропущенное целиком и брошенное без фактов счётчик этапа не повышают. Достижение объёма не переключает этап автоматически и не блокирует продолжение текущего. На последнем этапе программа продолжается до принятия другого плана.

`programs.advancePhase({expectedCursor,expectedHistoryRevision,confirmed:true})` доступен без активного занятия. Повторный CAS, проверка условия, запись нового курсора и сброс счётчика атомарны. Очередь дней сохраняется. История, профиль и версия программы не изменяются. Старые AI-ответы после смены этапа требуют нового запроса: `checkContext` сверяет `programPosition`, а analysis token включает курсор. Собственный импорт и rollback создают новую версию с первым днём и первым этапом.

`evaluateProgression` — чистая функция, выдающая только предложения. Для структурированных числовых условий используются последние N сопоставимых completed/partial сессий той же версии/этапа. Требуются все запланированные рабочие подходы исходного упражнения, известный совпадающий плановый/фактический вес и указанный правилами RIR. Разминка исключается, пропуски/замены не объявляются прогрессом. `upper_reps` требует верха диапазона всех рабочих подходов; `below_reps` — результата ниже минимума; `excessive_load` — недостижения минимума либо RIR ниже плана; `plateau` — одинаковых сопоставимых рабочих результатов минимум в двух сессиях. Индивидуальное правило имеет приоритет над общим для того же типа условия и действия. `manual`, условия времени/дистанции и неподдерживаемые смысловые критерии остаются рекомендациями для человека/ИИ; приложение не выдаёт вычисленный допуск.

Ни одна рекомендация прогрессии не меняет вес/повторы/подходы. Чтобы изменить базовую программу, пользователь передаёт анализ ИИ и подтверждает новую версию через прежний механизм. Помощь тренажёра и дополнительный вес сохраняют знак и смысл, заданные правилом.

## UI и повторный экспорт

Основной экран сохраняет параметры упражнения. Индивидуальный подход предзаполняется по своему `setPlans`; неизвестный вес остаётся пустым, после сохранения доступен отдых длительностью именно этого подхода. Подробности фаз, прогрессии и рекомендаций раскрываются отдельно до старта и во время занятия. Diff показывает новые данные отдельными русскими полями, а не сырой JSON.

«Скачать действующую программу» возвращает независимый `training_program` без профиля, внутренних UUID и фактов; полный план/этапы/правила/советы сохраняются при export → import → export. Это перенос плана, который при принятии начинается сначала. Точное продолжение текущего состояния — через резервную копию.

AI review содержит полную действующую версию, `programPosition:{phaseIndex,phaseSessions}`, прежние рекомендации/правила, до 20 последних completed/partial занятий со снимками и фактами, агрегаты всей завершённой истории и полный доступный каталог. План и факты позволяют ИИ увидеть отклонения; отдельная выдуманная оценка качества нагрузки не добавлена. Фото не включаются, замеры остаются по отдельному выбору. `programInstructions` уточняет новый контракт и разрешает definition вне каталога; прежняя literal-инструкция сохранена для старых пакетов. Старая и текущая сгенерированные responseSchema валидируются без переписывания исторического запроса.

Уточнение прежнего PRODUCT P11 по явному запросу владельца: импортированный план теперь может сохранять отдельную категорию nutrition в добровольно раскрываемых рекомендациях. Прежние nutritionTips 0–3, согласие профиля для генерации AI-советов, отсутствие дневника/медицинских назначений остаются. Повторный ответ с новыми nutrition-рекомендациями отклоняется без opt-in. Это сохранение рекомендаций программы, не новый модуль питания.

## Проверки и границы

Проверки и финальные результаты — в PROGRESS/TESTING. Native runner `tests/browser/program-extended.html` работает только на отдельном пустом origin: File/DataTransfer → настоящий компонент импорта → подтверждения → новый этап → старт → сохранение разминки → backup → полный reload → продолжение. Тестовые данные не смешиваются с пользовательским приложением. Runner не является системным file picker, тестом реального телефона или полной production/offline приёмкой.

Ограничения: нет автоматического применения правил и свободных выражений; нет автоматического поиска синонимов; определения пользовательского упражнения должны повторяться в каждой строке/override; замены пользовательского упражнения во время занятия пока не подбираются (можно пропустить); поддерживаемые единицы прежние — кг, секунды, метры. Внешняя методологическая оценка и реальные устройства остаются отдельной приёмкой.
