# AI Fitness Coach

## Расширенный обмен программами — IMP-02

В Тренере можно импортировать полный план с новыми упражнениями, этапами, правилами прогрессии и рекомендациями, затем скачать действующую программу. Новые упражнения и принятие плана требуют подтверждения; этапы переключаются явно, история сохраняется. Инструкция для ИИ содержит полный доступный каталог. [Контракт и решения](docs/PROGRAM_EXCHANGE.md), [JSON Schema](examples/training-program.schema.json), [полный пример A/B/C на 8 недель](examples/training-program.periodized.example.json). Старые schemaVersion:1 продолжают читаться; новых зависимостей/миграций нет. Результаты проверок и границы — [PROGRESS](docs/PROGRESS.md), [TESTING](docs/TESTING.md).

Готовую программу можно загрузить без предварительного AI-запроса: в Тренере откройте «Своя готовая программа» → «Как подготовить файл» → «Скачать формат для ИИ». Приложите формат в чат вместе с уже рассчитанным планом и попросите только оформить файл, не менять упражнения и нагрузку. Затем выберите полученный JSON, посмотрите дни/отличия и подтвердите свою программу. Поддерживаются 1–14 дней, до20 упражнений в каждом; пока только упражнения встроенного каталога. Пример: `examples/training-program.example.json`. В этой же отдельной форме можно импортировать только готовый план из прежнего AI-ответа, без принятия его анализа/советов. История и прежние версии сохраняются; активное занятие сначала нужно завершить.

При первом входе приложение сразу предлагает заполнить профиль для программы. Дополнительные сведения раскрыты и остаются необязательными; после «Сохранить и продолжить» открывается обычный экран. Сохранённый профиль используется при следующих входах без повторной анкеты. Фото и окружности можно добавить позже в «Прогрессе».

## Приватность и хранение — M6-03

В Профиле доступны резервная копия и раздел «Приватность и хранение». Приложение хранит данные локально без шифрования самим приложением. Старые ревизии профиля, AI-запросы/ответы/подтверждения могут содержать прежние добровольные сведения даже после изменения профиля/удаления замера. Фото не включаются в обычный AI JSON; внешняя передача выполняется пользователем отдельно.

Постоянное хранение проверяется автоматически, запрашивается только кнопкой. Браузер может отказать или не поддерживать API. Даже разрешённый режим не защищает от очистки сайта, приватного режима, потери устройства и не заменяет проверенную резервную копию.

Чтобы удалить всё: закройте остальные вкладки приложения, проверьте состав → поставьте отдельную отметку → «Удалить все локальные данные». Удаляются все ревизии, программы, история, активная тренировка/таймер, замеры, фото и сохранённые AI-пакеты; отмена ничего не меняет. Ошибка откатывает всю очистку. Изменение данных после просмотра требует нового просмотра. Останутся только неперсональный технический маркер и офлайн-оболочка. После удаления/восстановления перезагрузите страницу: старые формы заблокированы, reopen БД недостаточно. Старые версии вкладок до generation guard необходимо закрыть заранее.

Скачанные копии, оригиналы фото, другие браузеры и внешние AI-чаты удаляются отдельно. Старый backup может вернуть удалённые сведения при явном восстановлении. Физическое стирание носителя не гарантируется. Проверки и открытая native/телефон/диктор-приёмка — docs/TESTING.md и docs/PROGRESS.md. Новых зависимостей и миграции нет; коммитов и публикации нет.

## Начало работы
Нужны Node.js 22.23.1 (см. `.nvmrc`) и pnpm 11.19.0 (закреплён в `packageManager`). Допустимая ветка Node — 22, начиная с 22.13.0.

```sh
pnpm install --frozen-lockfile
```

Скопировать `.env.example` в `.env.local`, чтобы отключить телеметрию инструментов Next.js, затем:

```sh
pnpm dev
```

Открыть [локальное приложение](http://localhost:3000). Доступны `/`, `/workout`, `/progress`, `/coach`, `/profile`; главная и `/workout` отображают один экран тренировки. Навигация содержит четыре раздела. В production используется завершающий `/`.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:routes
```

`typecheck` сначала генерирует типы маршрутов Next.js. `test` запускает Vitest для UI/домена/хранилища и 6 Node-проверок PWA. `build` создаёт статический `out/`, затем генерирует `out/sw.js` из ресурсов этой сборки с SHA-256 integrity. Сервер Next.js не требуется. Перед сборкой остановите dev-сервер проекта, чтобы избежать конкуренции за `.next`. `test:routes` после сборки проверяет пять HTML-маршрутов, manifest/иконки и HTTP-доступность/целостность всех ресурсов PWA (7 тестов), затем закрывает временный loopback-сервер. Это тестовый сервер, не средство публикации.

CI (`.github/workflows/ci.yml`) выполняет эти же проверки на push и pull request с `pnpm install --frozen-lockfile`. Удалённый CI запускается после размещения репозитория владельцем. HTTP smoke не проверяет гидратацию или клики. Актуальные browser-результаты и открытые проверки телефона/диктора — в docs/TESTING.md; PWA добавлена в M6-01 ниже.

## Проверка прототипа M0-02

Запустите `pnpm dev`, затем откройте [демотренера](http://localhost:3000/coach/).

1. Нажмите «Открыть синтетическое демо». Реальный профиль из `/profile/` в него не передаётся.
2. Перейдите к импорту и нажмите «Импортировать демопример». До подтверждения программы нет. Попробуйте отклонить и повторно открыть пример.
3. Подтвердите программу, перейдите к тренировке и начните занятие одним нажатием.
4. Введите демонстрационный вес (изначально он неизвестен), оставьте 10 повторений и запишите подход. RIR можно не заполнять. При желании исправьте факт.
5. Перейдите между четырьмя разделами: записанный факт остаётся, активное занятие можно продолжить. Просмотр обновления при активном занятии заблокирован.
6. Завершите неполную тренировку. В итоге показаны один выполненный подход, неполнота и следующее занятие Б.
7. Откройте пример обновления: отдых в жиме ногами 90 → 120 секунд, причина и влияние видны до принятия. «Оставить текущую» сохраняет версию 1; «Применить весь пакет» включает версию 2 с началом последовательности с А.
8. В «Прогрессе» остаются прежние фактические числа и версия программы на момент занятия.

Состояние демо существует только в памяти React и сохраняется при переходах через навигацию приложения. Перезагрузка, новая вкладка и прямой повторный вход начинают чистое демо. Для повторения без перезагрузки: Тренер → О демоданных → Начать демо заново. Реальный профиль при этом не меняется.

В отдельном раскрываемом блоке «Отдельное синтетическое демо» импорт заменён готовым примером. Реальный обмен расположен выше и не передаёт данные в демо. Реальные таймер, замены и пропуски доступны в основной тренировке, добровольные фото — на Прогрессе, резервные копии — в Профиле. Не вводите реальные персональные сведения в демо. Все его цифры служат оценке интерфейса. После одного демоподхода сценарий занятия заканчивается; это не полноценный дневник.

Актуален третий макет «Технологичный» — владелец исправил первоначальный выбор. Реализованы градиентный знак, светящиеся орбиты, стеклянные карточки с контуром, диагональный блик, векторные иллюстрации упражнений и градиентная основная кнопка. Radix и Lucide сохранены. [Референс](docs/design/technology-reference.png), [реализация 390 px](docs/design/technology-390.jpg), [реализация 360 px](docs/design/technology-360.jpg).

## Архитектура прототипа

- `app/` — корневой layout, глобальные стили и тонкие адаптеры маршрутов.
- `src/views/{workout,progress,coach,profile}/` — экраны с публичными API `index.ts`.
- `src/widgets/app-shell/` — переиспользуемая оболочка с содержимым через `children`: отдельная область прокрутки и меню, постоянно закреплённое в нижней строке окна. Крупный текст увеличивает строку меню, не перекрывая содержимое. [Снимок](docs/design/technology-fixed-menu.jpg).
- `src/widgets/ux-prototype/` — изолированный демонстрационный слайс: чистый reducer, временный provider и клиентские экраны. Layout оборачивает серверные children provider-ом; навигация и адаптеры остаются серверными. Публичный API слайса используется из layout/views, импорты направлены сверху вниз. Состояние прототипа не является будущей доменной моделью или заменой IndexedDB.
- `src/shared/ui/` — общие адаптеры Radix: Button, Input, Textarea, Select, Accordion. Здесь нет знания маршрутов или домена. Theme подключён в корневом layout; прежняя заглушка сохранена, но не используется.
- `tests/` — интеграционные smoke-проверки, вне слоёв приложения.

Пустые слои FSD не создаются. Доменные схемы и адаптеры хранилища находятся в `src/entities/training` (см. ниже). `features/edit-profile` подключает реальный профиль; `features/coach-exchange` — обмен и подтверждение; `features/next-workout` — сохранённую последовательность и тренировку. Views компонуют их с оболочкой и отдельным демо. Старт/resume, подходы, отдых, замены, пропуски и завершение используют реальную IndexedDB-сессию; features/training-progress показывает реальные итоги и историю упражнений. Service worker и офлайн-загрузка приложения ещё не реализованы. Внешние шрифты, аналитика, backend и регистрация отсутствуют.

## Домен M1-01

Публичный API — `src/entities/training/index.ts`. Один связный доменный слайс объединяет профиль, каталог, план и факт, чтобы схемы снимков не требовали межслайсовых импортов entities. Внутренние модули не зависят от React, Next, прототипа или инфраструктуры. Типы выводятся через `z.infer`; объекты strict, без приведения строк к числам и без выдуманных defaults, результат валидации readonly и заморожен в глубину.

- `profileSchema`: цель, опыт, частота с null, оборудование с unknown; дополнительные сведения отсутствуют либо null, каждое поле добровольно.
- `programDraftSchema` проверяет план без внутренних ID; `programVersionSchema` — неизменяемую версию с UUID, предыдущей версией, ревизией профиля и упорядоченными шаблонами/строками. Порядок задают массивы.
- `workoutSessionSchema` хранит снимок шаблона, версию, время, статус и отдельные факты. В факте повторы — число, в плане — диапазон. Пропуск не содержит результата. Проверяются связи со снимком, индексы, дубли и временные границы. Это описание данных, ещё не операции сохранения/завершения.
- Восемь авторских записей каталога охватывают базовые движения и reps/duration/distance; это не назначенная программа. Вес — кг, время — секунды, дистанция — метры. Каталог различает внешний вес, добавленный вес тела, помощь и способ учёта гантелей. Неизвестный вес/RIR сохраняется как null, отсутствие RIR допустимо; время/дистанция не получают вес или RIR. Тоннаж не вычисляется.

После M1-02 все пять команд проверок проходят (Vitest 110/110, HTTP 5/5). Worker-проверки в Windows выполнялись с расширенным доступом после sandbox `spawn EPERM`. Проверен только `proposedProgram` из синтетического response-примера; AI-конверты и request-пример ещё не валидируются. Репозитории проверяют ссылки на сохранённые версии, ревизии и атомарность записи сессии. Проверка оборудования профиля/ограничений и физиологическая безопасность — последующие задачи. Фото/замеры, AI-контракты и backup заранее не создавались. Подробные решения — `docs/DATA_CONTRACTS.md`, результаты — `docs/PROGRESS.md`.

## Хранилище M1-02

Публичный API: `createTrainingStorage()` из `src/entities/training`. Создавайте адаптер в клиентской части, явно вызывайте `await storage.open()` и `storage.close()` при окончании работы. Импорт модуля не открывает БД. `profiles.current/get/save` сохраняют последовательные ревизии одного профиля; `programs.get/list/append` добавляют неизменяемые версии без активации; `sessions.get/list/historyRevision/save` сохраняют целый снимок и счётчик истории атомарно. `sessions.save(input, expectedHistoryRevision)` возвращает новую ревизию после commit. Повторный вызов со старой ревизией отклоняется. Все входы/выходы проверяются схемами; возвращаемые доменные значения заморожены. Ошибки возвращаются вызывающему коду; UI будущих задач должен показывать их и предлагать повторное действие.

`src/shared/infrastructure/db/index.ts` содержит только Dexie, индексы и примитивные envelopes с `payload: unknown`. Адаптер домена выполняет проверки связей. Историческая схема M1-02: БД `ai-fitness-coach`, v1: `profileRevisions`, `programVersions`, `sessions`, `counters`. Каталог статический. В M2-02 добавлены две AI-таблицы v2 (см. ниже); настройки, курсор, фото и backup этим срезом не добавлялись. Старые ревизии профиля сохраняются для связи с программами. ## Начальный AI-обмен M2-02

1. Сохраните профиль на `/profile/`; добровольные поля можно пропустить, оборудование может быть неизвестно.
2. На `/coach/` прочитайте состав передаваемых категорий. Нажмите «Скачать запрос для ИИ» или «Скопировать запрос с инструкцией». Приложение сначала атомарно сохраняет запрос в IndexedDB, затем вызывает браузерное действие. Скачивание запрашивается у браузера; приложение не может подтвердить конечное сохранение через менеджер загрузок. Ошибка копирования/локальной записи не выдаётся за успех.
3. Самостоятельно передайте файл выбранному внешнему ИИ. Инструкция и JSON Schema уже внутри. Приложение не подключается к AI API и не отправляет профиль автоматически. Файл чувствителен: содержит и заполненные добровольные сведения. Фото/контакты/замеры не входят.
4. Выберите UTF-8 JSON до 2 MiB в поле «Ответ ИИ». Проверяются strict Zod, версии, сохранённый requestId, контекст, текущие ревизии, каталог, оборудование, питание и отсутствие active-сессии. Чужой/устаревший ответ отклоняется без изменения программы/истории.
5. Прочитайте полный предпросмотр: интерпретация цели, причины, порядок занятий, все упражнения/параметры/заметки и питание по согласию. До подтверждения программы нет. Видно, что новая последовательность начнётся с первого шаблона.
6. После оценки пакета и своих ограничений отметьте подтверждение просмотра, затем нажмите «Применить весь пакет». При сомнениях нужна оценка специалиста: валидация JSON не подтверждает безопасность нагрузки. Версия, активная программа, начальный курсор и принятый ответ сохраняются одной транзакцией. «Отклонить ответ» удаляет только непринятый предпросмотр; его можно импортировать снова.
7. Перейдите «К следующему занятию»: видны первое занятие и порядок остальных, без обязательных дат. Перезагрузка сохраняет программу и позицию. Нажмите «Начать тренировку» — сессия и снимок плана сохранятся локально. После reload/возврата нажмите «Продолжить тренировку»; нового занятия это не создаёт.
8. «Завершить занятие» сначала показывает последствия и позволяет продолжить. Сохраняйте подходы по одному; предзаполнение становится фактом после commit. Неизвестный вес оставьте пустым, RIR доброволен. Сохранённый подход можно явно исправить. Полное/частичное завершение двигает курсор один раз; без результатов сохраняется abandoned с прежним курсором. План не подменяет факт, демо хранится отдельно.
9. «Отдых N с» запускает сохраняемый таймер; после возврата остаток считается по deadline. «Заменить или пропустить упражнение» предлагает каталожные варианты для явного выбора либо пропуск оставшихся подходов. Вес замены подбирается заново, исходная программа не меняется. Открытый черновик при замене сохраняется; явно закройте его и откройте новую форму.
10. Пропуск подхода/упражнения не считается результатом и сам не двигает очередь. До старта можно отдельно подтвердить «Пропустить целое занятие»: сохраняется skipped без подходов и очередь двигается один раз. При активном занятии сначала продолжите или завершите его, факты не удаляются. Офлайн-загрузка и фоновые уведомления пока не реализованы.

До принятия повторный импорт актуального запроса обновляет одну запись предпросмотра. Закрытие просмотра скрывает его на экране; сохранённый ответ остаётся в БД. При входе восстанавливается ответ самого нового запроса; более ранний актуальный ответ можно открыть повторным импортом своего файла. Принятие заново проверяет сохранённый запрос, показанный пакет, accepted-статус, ревизии профиля/истории, activeVersion и отсутствие active-сессии в одной транзакции. Изменённый другой вкладкой пакет нельзя подтвердить молча. Повторное принятие/импорт принятого запроса отклоняется; ошибка записи откатывает весь пакет.

UI поддерживает initial до первой сохранённой программы/истории и review-экспорт активной программы (M4-02). Сравнение и принятие повторного ответа — M4-03, ещё не реализованы. Низкоуровневый `programs.append` не означает активную программу. Предложение требует человеческой оценки; автоматического доказательства физиологической безопасности нет. `needs_input`/`unsupported` не применяются; `keep` на уровне адаптера принимает анализ без новой версии или изменения курсора (UI принятия review ещё отсутствует).

БД v3 (native IndexedDB 30): исходные v1/v2 сохранены, v3 добавляет `programState` и `coachAcceptances`. Миграция сохраняет прежние записи без автоматической активации низкоуровневых версий. Регрессионный rollback/unknown-version стенд использует тестовую v4. Public API `storage.coach`: `createInitialRequest`, `createReviewRequest`, `getRequest`, `latestRequest`, `importResponse`, `preview`, `accept`, `acceptance`, `reject`; `programs.active` читает версию/курсор/следующий шаблон согласованно. Новых зависимостей нет. UI — `features/coach-exchange` и `features/next-workout`, композиция — views; демо изолировано. Подробные результаты и ограничения — PROGRESS/TESTING.

## M5-01 — локальный прогресс (25.11.2026)

«Прогресс» показывает текущую сохранённую цель, полные/частичные/пропущенные занятия и работу каждого фактического упражнения за всю историю версий. Повторы, секунды и метры разделены. График появляется от двух занятий, показывает последние 12 от ранних к поздним; в раскрытии — фактические подходы, даты, веса, RIR и замены. Более ранние занятия доступны порциями по 12. Без результатов нет пустого графика или обязательного сбора дополнительных сведений.

Сумма повторов — работа при сохранённых условиях, без оценки силы, физиологического улучшения или процента достижения свободной цели. Веса не суммируются; помощь тренажёра, добавочный вес и вес одной гантели явно подписаны. Unknown отличается от 0. Только done в completed/partial увеличивают объём; другие статусы учитываются отдельно. Согласованное чтение IndexedDB не пишет данные; подписка обновляется после изменений другой связи, ошибка требует явного повтора. Новых зависимостей и изменений схемы БД нет. Замеры/фото/питание M5-02/03 не начаты. Проверки и ограничения — TESTING и PROGRESS.

### M5-02: замеры и локальные фото

В `/progress/` раскрывается необязательный раздел: масса тела/окружности с локальной датой, просмотр и удаление, фото по одному с подтверждением удаления выбранных/всех показанных. JPEG/PNG до5МиБ/4096px/12Мп преобразуется локально в новую JPEG-копию до1600px/2МиБ без исходного имени/EXIF; максимум20фото и1000замеров. Фото и данные не отправляются автоматически. Оригиналы храните отдельно. PWA и backup доступны; ограничения проверки — в разделах M6 и docs/TESTING.md.

В `/coach/` можно отдельно выбрать типы замеров для конкретного экспорта: попадут только последние90дней. По умолчанию замеров нет, фото в JSON не включаются никогда. Для отдельного фото доступен явный выбор, предупреждение и скачивание очищенной копии для самостоятельной передачи внешнему ИИ. Изменение включённых замеров делает старый AI-ответ неактуальным. Удаление записи здесь не удаляет ранее сохранённые AI-снимки/внешние копии.

БД обновляется v3→v4 добавлением двух таблиц без переписывания старых данных; прежнее приложение не совместимо с новой версией БД, данные не очищать. `pnpm test:db:browser`, затем `/tests/browser/body.html` на4174 — отдельные native проверки синтетических фото и временной БД m5-02-native-*. Состав, команды, результаты и ограничения — [TESTING](docs/TESTING.md) и [PROGRESS](docs/PROGRESS.md). M5-03 реализована ниже, коммитов/публикации нет.

## Добровольное питание (M5-03)

В дополнительных сведениях профиля можно включить короткие советы. Экспорт уже включает nutritionOptIn; ответ допускает0–3пункта до180символов, без согласия импорт отклоняет непустой список. В Тренере отдельный раздел показывает советы из принятого анализа активной программы. Новый экспорт их не стирает. Пустой принятый список заменяет прежние советы; изменение профиля или возврат программы требует нового принятого анализа. После сохранения отказа советы скрыты, исторические пакеты остаются локально. Сеть/калории/медицинские назначения не добавлены; смысл советов внешнего ИИ пользователь оценивает сам.

DBv4/контракты/инструкция старых запросов/зависимости неизменны. ## M6-01 — установка и офлайн (25.11.2026)

В production под разделами есть «Ресурсы для офлайн загружены». Дождитесь этого статуса при первом подключении: загружаются все пять экранов, CSS/JS, файлы переходов Next.js и иконки. Затем приложение можно открывать и использовать без сети. Внешний чат ИИ требует интернета; создание/чтение локальных файлов выполняется на устройстве. Установка необязательна: Android/desktop — меню браузера «Установить приложение»/«На экран Домой», iPhone Safari — «Поделиться» → «На экран Домой»; доступность зависит от браузера. При отказе хранения или неполной загрузке готовность не показывается, есть повтор подготовки. Установка не защищает данные от удаления браузером и не заменяет backup (M6-02).

Новая сборка загружается в отдельный кеш. Автоперезагрузки и принудительной смены кода во время занятия нет. Если появилось сообщение об обновлении, завершите работу и закройте все вкладки/окна приложения. При следующем открытии браузер активирует новую версию. IndexedDB, история, фото и AI-пакеты service worker не читает/не удаляет. Обычная HTTP CacheStorage содержит только заранее перечисленные публичные ресурсы сборки. Не очищайте данные сайта ради обновления.

PWA проверяется на production export, не через `pnpm dev` (регистрация там отключена). Для локального теста: проверьте свободный порт, в PowerShell `$env:FITNESS_TEST_PORT='4180'`, затем `node tests/profile-browser-server.mjs`. Используйте отдельный синтетический origin. Для размещения (только после разрешения владельца): HTTPS, корень домена `/`, весь out целиком; `/sw.js` с `Content-Type: text/javascript` и `Cache-Control: no-cache`, manifest с `application/manifest+json`, `.txt` с `text/plain`, папки `/workout/` и т.п. отдают свой index.html. Не подменять отсутствующий JS/TXT общим HTML fallback, не включать query-injection стенда. `next.config` headers не работают на статическом хосте — заголовки настраивает хост. Публикация не выполнена.

Автоматические проверки: lint/typecheck/build,456 Vitest +6 PWA,7 HTTP smoke; финальный кеш48ресурсов. Native Chrome на4180: полная подготовка, сохранение синтетического профиля, остановка сервера, reload/новая вкладка/переходы по разделам с чтением IndexedDB, затем сообщение ожидающего обновления. Активация финальной версии, перезапуск процесса/установка/реальный телефон/офлайн запись подхода и таймер не подтверждены; точные ограничения — TESTING. Старые разделы README описывают результаты прежних этапов; этот раздел задаёт актуальный статус PWA.

## Резервные копии M6-02

Профиль → «Резервная копия» → «Скачать резервную копию». Фото по умолчанию исключены; отметка включает все текущие локальные снимки. JSON содержит все ревизии профиля, версии программы, историю/активное занятие/таймер, замеры и старые AI-пакеты с чувствительными добровольными сведениями. Файл не зашифрован; храните его в надёжном месте. Действие запускает скачивание, сохранение в загрузках нужно проверить. Локальное хранилище может быть удалено браузером; внешние копии приложение не удаляет.

Восстановление: сначала сохраните текущую копию, завершите активное занятие, закройте другие вкладки приложения (особенно со старой версией приложения). Выберите JSON приложения до96MiB; прочитайте дату/состав/количества, отметьте подтверждение полной замены и нажмите «Заменить данные этой копией». Отмена до применения ничего не меняет. Замена затрагивает программу, всю историю и фото; **копия без фото удаляет текущие фото**. Объединения нет. После успеха перезагрузите страницу; старые формы блокируются, в открытых вкладках показывается предупреждение перезагрузки. Активная сессия из копии восстанавливается со своим снимком/фактами/таймером/курсором.

Формат `fitness_backup`, version1/databaseVersion4, один JSON-архив с JPEG в base64, без ZIP/сжатия/путей и новых зависимостей. Неизвестные версии, чужие AI JSON, невалидные связи/данные/фото отклоняются до записи. Запись всех таблиц атомарна; отказ откатывает замену. Повторное подтверждение после изменений в другой вкладке требует нового предпросмотра. Копия не является файлом запроса для ИИ и не отправляется автоматически. Не редактируйте файл вручную.

`pnpm test:db:browser`, затем `http://127.0.0.1:4174/tests/browser/backup.html` — подготовленный native runner:10 общих сценариев и1 фото/Blob/decoder/quota/retry. Он использует только временные синтетические БД. В M6-02 runner и production UI вручную НЕ запускались: доступное окно Chrome свёрнуто, браузерных провайдеров нет; прежний about:blank после URL-policy не использовался. Автоматические fake-IDB тесты не подтверждают native lifecycle/physical quota/телефон. Актуальные результаты — docs/PROGRESS.md и docs/TESTING.md.
