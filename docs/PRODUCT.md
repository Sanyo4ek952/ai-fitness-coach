# Product specification — MVP v1

## Уточнение UX-05 (26.11.2026, утверждено владельцем)

Владелец утвердил пять макетов тренировки в docs/design/workout-ux05 и поручил реализацию с сохранением их компоновки и цветов. Фокус активного занятия — одно упражнение и один редактор подхода, план отделён от факта. Автоотдых после успешного сохранения можно отключить; компактный таймер раскрывается в крупный, доступна поправка ±15с текущего отдыха. Это не изменение программы. Завершение подтверждается, неполные/пропущенные подходы не становятся результатами; следующий экран — предпросмотр следующего занятия. Ошибки сохраняют ввод. Адаптивный перенос и прокрутка обязательны при длинных названиях/увеличении текста; внешние рамки и аннотации макетов не являются частью UI.

## Уточнение IMP-02 (26.11.2026, явный запрос владельца)

Ограничение IMP-01 восемью упражнениями снято: полный встроенный/пользовательский каталог передаётся ИИ. Новое упражнение с полным определением показывается в preview и требует согласия; подмена похожим запрещена. Сохраняются этапы нагрузки, структурированные правила прогрессии, категории рекомендаций и отдельные параметры подходов. Недельный этап означает заданный объём сессий, а не срок по календарю; переход подтверждается спортсменом. Правила дают предложения, любое изменение плана по-прежнему требует принятия.

Уточнение P11: по этому запросу импортированная программа может сохранять nutrition в отдельно раскрываемых рекомендациях. Прежние краткие nutritionTips, opt-in для новых AI-советов, запрет дневника калорий и медицинских назначений сохраняются. Полный контракт, границы и решения — [PROGRAM_EXCHANGE](PROGRAM_EXCHANGE.md). Самостоятельный экспорт переносит полный план с началом с первого дня/этапа; резервная копия сохраняет текущее продолжение. Более ранние описания ограничений IMP-01 ниже являются историей.

Статус: концепция утверждена пользователем; технические детали ниже — рабочие решения, проверяемые прототипом.

## Ценность
Спортсмен тренируется, ИИ анализирует, приложение организовывает. Основной результат — следующий конкретный шаг к цели без необходимости вести переписку с ИИ и повторять контекст.

## Аудитория и область применения
Взрослые посетители спортзала любого уровня, включая начинающих и опытных. Цель вводится свободно (можно выбрать подсказку); допускаются сила, гипертрофия, изменение массы тела, выносливость и сочетания. Произвольная цель не означает обещание достижимости или медицинскую реабилитацию. Спортивная подготовка высокого уровня может требовать специалиста. MVP не предназначен для детей и медицинских назначений.

## Требования (P0 — обязательно для v1)

| P15 | Импорт безопасен: ошибки, чужие/устаревшие ответы, дубликаты и неизвестные схемы не меняют текущую программу. |

## Главный сценарий

Уточнение IMP-01 (26.11.2026, запрос владельца): пользователь может отдельно импортировать свою уже составленную программу, оформленную внешним ИИ, без предварительного экспорта и `requestId`. В «Тренере» раздел «Своя готовая программа»: инструкция с форматом/каталогом без личных данных → выбор файла → проверка/предпросмотр дней и отличий → явное согласие и принятие. Приложение не пересчитывает план и не заменяет упражнения. В этой явно выбранной форме допустимо извлечь только `proposedProgram` из старого валидного `coach_response`; его request/context/summary/reasons/nutrition не считаются актуальным AI-анализом и не принимаются. Обычный импорт ответов сохраняет прежнюю строгую привязку к запросу.

Подтверждение своего плана создаёт новую версию и начинает с первого дня, не меняя историю, прежние версии или профиль. Нельзя применить при активном занятии или изменившемся контексте просмотра. Сохраняются ограничения DTO (1–14 дней, 1–20 упражнений в дне), каталог приложения и проверка оборудования профиля. Произвольные новые упражнения вне нынешнего каталога этим срезом не добавлены; вопрос о них задан владельцу отдельно. Это дополнительный добровольный сценарий, исключение из необходимости предварительного экспорта P03, а не ослабление P15 для обычных AI-ответов.

Уточнение UX-04 (26.11.2026, утверждено владельцем): выбор ответа ИИ показывает имя/размер файла, но не читает и не импортирует его. Отдельная кнопка «Отправить» запускает локальную проверку и сохранение предпросмотра; ошибка сохраняет выбранный файл для повтора. Выбор другого файла скрывает старое предложение и сбрасывает отметку просмотра. После успеха фокус переводится к предложению. Это не отправка во внешний сервис и не принятие программы.

Предложение показывает короткое резюме, все дни программы отдельными аккордеонами без фотографий (1–14 по существующему контракту). Первый день раскрыт, остальные доступны по нажатию; внутри сохраняются все упражнения, подходы, цели, веса/неизвестность, отдых, RIR и примечания. Причины, цель/срок анализа и вычисленные отличия доступны в отдельных раскрытиях. Перед применением пользователь по-прежнему подтверждает просмотр всего пакета; новая версия не меняет историю. Это согласованное изменение только импорта/предпросмотра, не утверждение остальных предложений UX-03.
При первом открытии без сохранённого профиля приложение сразу предлагает анкету для составления программы. Все существующие дополнительные поля раскрыты, их назначение объяснено; они остаются добровольными. После сохранения открывается исходный раздел, повторного заполнения при следующем входе нет. Фото и окружности предлагаются отдельно в «Прогрессе», без требования приложить их для начала. Восстановление прежнего профиля из резервной копии доступно через Профиль.

До принятия первой программы «Тренер» начинает с полной анкеты, даже если профиль уже сохранён. Ответы подставляются из IndexedDB; дополнительные сведения сразу раскрыты. Перед первым экспортом в текущем посещении нужно проверить и сохранить ответы. Дополнительные значения разрешено пропустить, неизвестные не выдумываются. Только после успешного сохранения доступны скачивание и копирование запроса; ответы можно дополнить до экспорта. При изменении профиля другой вкладкой проверка требуется заново. После принятия программы анкета в «Тренере» не показывается. Прямой вход в «Тренер» использует эту анкету без отдельного стартового редактора оболочки; остальные разделы сохраняют стартовый сценарий UX-01. Импорт уже полученного ответа остаётся доступным.

1. Создать профиль (один раз). 2. Проверить сведения для первого плана, скачать файл для ИИ и инструкцию. 3. Передать в выбранный чат, получить JSON. 4. Импортировать, посмотреть краткий план, подтвердить. 5. Начать занятие, фиксировать подходы. 6. Завершить, увидеть следующее занятие. 7. При сигнале анализа экспортировать новый файл, импортировать решение, подтвердить изменения.

## Необычные ситуации
Пропуск даты: последовательность не сдвигается сама. Пользователь может отложить, пропустить целую тренировку (явно) либо продолжить её позже. Частичная тренировка: выбор завершить/продолжить; завершённая частичная считается пройденной, но маркируется как неполная. Замена тренажёра на занятии — выбор пользователя, не автоматическая правка программы; предложить варианты из каталога, сохранить связь с исходным упражнением. Если нет безопасной замены — пропустить. Изменение цели — запрос анализа без удаления истории. Острые симптомы — краткий сигнал остановить упражнение и обратиться за помощью по ситуации; не ждать ответа ИИ.

## Не входит
AI API внутри приложения, аккаунты, облачная синхронизация, дом/улица как отдельные режимы, социальные функции, автоматическая оценка процента жира по фото, медицинская диагностика, лечение, сложный трекинг питания, подписки, нативные магазины. Локальные фото и добровольные замеры входят в v1; видео, голос и часы — позже.

## Продуктовые критерии (проверяемые цели, не доказанные результаты)
- Первичная анкета без опциональных данных: целевой медианный результат ≤ 90 сек у тестовой группы (без внешнего чата).
- Старт занятия ≤ 2 нажатий, фиксация неизменённого подхода — 1 нажатие.
- Ни одного обязательного повторного вопроса об уже известной цели.
- После импорта понятно, что делать дальше; главная рекомендация ≤ 3 коротких пунктов.
- Не менее 2–4 недель реального использования до релиза; измерить потерю данных, ошибки импорта и лишние действия; не считать это доказательством физиологической эффективности.
